# Jiraの画像付きQAコメントを下書きにする

## 手順

1. 対象チケット・QA文書・掲載する画像・対応行を確認する。本文のテンプレートと結果は維持する。
2. 使用可能なコネクタの添付対応を確認する。利用できなければ既存の操作許可に従ってブラウザを使用する。ログインが必要ならユーザーに依頼し、既存のコメント下書きを確認してから編集する。
3. 本文と表をコメント編集欄へ入力する。画像を除いたHTMLを貼り付ける場合も、見出し・表の7列・各ケースの内容を照合する。
4. 画像をファイルアップロードまたは画像の実データの貼り付けとして取り込む。Jiraがアップロードを行いメディアノードを作成する操作を使い、画像タグをDOMへ追加するだけで代用しない。
5. アップロード完了後、画像を対応するエビデンス欄に配置する。非同期アップロードで挿入位置がずれることがあるため、1枚ごとに行と画像を確認する。
6. 下記の検証を行い、送信指示がなければ保存ボタンを押さず下書きで止める。ユーザーには対象チケットと編集状態を案内する。

## 画像形式・操作上の注意

- `pbcopy`のテキスト、HTML内のdata URI、localhost・IDEプレビューサーバー・ローカル絶対パスは、画像をJiraへ添付する処理と同等ではない。手元で表示できても他の閲覧者への共有を保証しない。
- ブラウザがアップロード済み画像の表示にblob URLを使うことはある。URLの見た目だけで判定せず、アップロード応答とJiraのメディアIDを確認する。
- APIで添付する場合も、添付の存在と本文内の配置は別に検証する。コメント投稿APIを下書き作成の代用として呼ばない。
- ブラウザのFile／DataTransferによる画像貼り付けを使う場合は、正規エディタの貼り付け処理に渡す。実データの長さ・ファイル名・形式を照合し、大きなbase64のツール出力が切れていないことを確認する。
- 再配置では既存メディアIDを保持するエディタのコピー／貼り付けを使える。アップロードし直す前に既存画像を再利用できるか確認する。期限付きURLや認証トークンを文書へ保存しない。

## 完了前の検証

- 表の見出し・列数・行数と、手順・期待結果・判定が元のQA文書と一致する。
- 各画像のアップロードが成功し、メディアIDがある。画像枚数だけでなく、各エビデンス行と画像内容の対応を確認する。
- 全画像が表示され、必要な情報を読める。画像を開く操作が可能なら原寸でも確認する。
- 本文の画像参照にlocalhost・ローカルファイル参照が残っていない。
- 下書きなら「アップロード済み・コメント未送信」と報告する。他ユーザーからの閲覧確認やチケットへの関連付け完了を、下書き状態で確認済みとしない。
- 投稿が明示的に許可されている場合は保存後にコメントを再読込し、表・画像・添付の関連付けを確認する。
