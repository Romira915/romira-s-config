# スクリーンショットエビデンスの表示

QA 実行後、取得済みスクリーンショットを結果表へ掲載する場合に読む。

## エビデンスセルへの埋め込み

- スクリーンショットのファイル名だけをエビデンスセルへ並べない
- HTML の表内では Markdown 画像記法が表示されないレンダラーがあるため、`<img>` を使ってセル内へ画像を直接表示する
- 画像をクリックして原寸確認できるように、同じ相対パスの `<a>` で囲む
- 表示用のファイル名は、第三者の合否判定に寄与しないため原則として記載しない。添付作業上どうしても識別子が必要な場合だけ記載する
- 各画像の直前に、第三者が画像を開く前から判断箇所を特定できる短い説明を書く。説明は「画面上のどこを見るか」と「何が確認できるか」を含める
- 複数画像がある場合は、それぞれを期待結果と対応する順序で同じセル内へ表示する
- ローカル絶対パスは書かず、QA Markdown からの相対パスを使う

```html
<p><strong>確認箇所・結果：</strong>「結果」画面のステータス欄が「完了」になっている。</p>
<a href="../../evidence/<ticket>/test1_result.png"><img src="../../evidence/<ticket>/test1_result.png" alt="結果画面の完了ステータス" width="640"></a>
```

Jira へ貼り付ける場合は、画像を Jira から参照できる添付へ変換したうえで同じセル内に表示する。Jira がローカル相対パスを解決できないことを理由に、ファイル名だけの一覧へ戻さない。

## 掲載画像の選別

- 撮影した画像をすべて掲載せず、第三者が期待結果を判定するために必要十分な画像だけを残す
- 各画像に、その画像だけが担う確認事項を1つ以上割り当てる。画像を削除しても合否判定に影響しないなら掲載しない
- より強い画像に同じ情報が含まれる場合、入力途中・遷移途中・最終確認などの弱い画像は掲載しない
- 同じメールの受信詳細とメール原文などが同じ宛先・件名を示す場合は、認証結果等も同時に示せる強い方を優先する
- 画像の枚数ではなく、期待結果を重複なく説明できることをエビデンスの品質基準にする

## 検証

- `src` と `href` が指す全ファイルが存在する
- 0 byte ではなく画像形式として認識できる
- 画像を開き、合否判定に必要な表示が読める
- 秘密情報や不要な個人情報が写っていない
- エビデンス列の画像数と参照するファイル数が一致する
- すべての画像に「どこを見て何を確認するか」の説明がある
- すべての画像に固有の確認事項があり、他の画像だけで同じ判定を完結できない
