# Notion タスク追加スキル

URL・画像・テキストから情報を抽出し、Notionのタスクデータベースにタスクを追加するスキル。

## 入力ソース

このスキルは以下の入力ソースに対応する:

| ソース | 例 | 抽出方法 |
|---|---|---|
| URL | X/Twitter投稿、通販サイト、公式サイト | `web_fetch` → `web_search` フォールバック |
| 画像 | 雑誌のプレゼント応募ページ、チラシ、スクリーンショット | 画像内テキストを直接読み取り |
| テキスト | ユーザーの直接入力 | そのまま使用 |

## 既知のデータベース情報

ユーザーが頻繁に使うデータベースの情報。新規DB指定がない限りこちらを使用し、`Notion:fetch`をスキップして効率化する。

### メインタスクDB

ユーザーが頻繁に使うデータベースの接続情報は、スキル本文に個人固有の値を直書きしない。実行時に `~/.claude/personal.md` を Read し、`notion-task-from-url` セクションから以下を取得する。

- DB URL
- data_source_id
- 最新スキーマ

設定が見つからない場合やユーザーが別のDB URLを指定した場合は、`Notion:fetch` で最新のDBスキーマとdata sourceを取得する。
## ワークフロー

### Step 1: 入力ソースから情報を抽出

#### URLの場合

**取得の優先順序:**
1. `web_fetch` で直接取得を試みる
2. ブロックされた場合は `web_search` でキーワード検索
3. 関連ページ（公式サイトのニュースページ等）から間接的に情報を取得
4. それでも不足する場合はユーザーに確認

**X（Twitter）のURLの場合:**
- robots.txtでブロックされることが多い
- アカウント名 + キーワードで `web_search` する
- 公式サイトのニュースページにも同じ情報が載っていることが多い
- 通販URLが含まれていればそちらも合わせて取得する

#### 画像の場合

ユーザーがアップロードした画像（雑誌ページ、チラシ、スクリーンショット等）から以下を読み取る:
- タスクに関連するテキスト（商品名、イベント名、人名等）
- 期限・締切の日時情報
- 応募方法や注意事項
- 参照URL（画像内に記載があれば）

**画像読み取りのポイント:**
- 日本語の縦書き・横書き両方に対応
- 部分的に隠れている・ぼやけている情報は推測せずユーザーに確認
- 画像だけでは不足する情報（雑誌名等）は積極的にユーザーに質問

#### 抽出すべき情報

- タスク名（商品名、イベント名、応募対象等）
- 期限日時（予約期限、応募締切、消印有効日等）
- カテゴリ/タグに使える情報
- 参照URL
- 応募方法・手順の詳細

### Step 2: プロパティのマッピングと確認

`ask_user_input_v0` を使って **必要な確認事項をまとめて1回で聞く**。

**まとめて確認すべき項目:**
1. タグ（既存の選択肢から推測 + 確認）
2. タスク名の不明点があれば（雑誌名、商品の正式名称等）

**自動判定できるもの（確認不要）:**
- ステータス → 原則「未着手」
- Priority → **デフォルト「緊急」**（ユーザーから別途指定がない限り）
- Privacy → **デフォルト「Public」**（ユーザーから別途指定がない限り）
- タグ → コンテンツの内容から明らかな場合は自動選択（例: 蓮ノ空関連 → タグ「蓮ノ空」）、ただし選択肢には含めて確認
- 日付 → 抽出した情報から自動設定

**マッピング時の注意点:**
- ユーザーが指定した値がselectの選択肢に完全一致しない場合は、ユーザーに確認する
- 日付は ISO-8601 形式（`YYYY-MM-DD`）で設定
- 「当日消印有効」「〜月末日」等の表現は適切な日付に変換（例: 3月末日 → `YYYY-03-31`）

### Step 3: タスク作成

`Notion:notion-create-pages` でタスクを作成する。

**ページ作成時のポイント:**
- `parent` には `data_source_id` を使用
- `properties` にはスキーマに合わせた値を設定（**Privacyも初回作成時に含める**）
- `content` にはMarkdownで補足情報を記載

**propertiesの設定例:**
```json
{
  "名前": "Love Voice mag. 月音こな サイン入りチェキプレゼント応募",
  "ステータス": "未着手",
  "Priority": "緊急",
  "タグ": "[\"蓮ノ空\"]",
  "date:日時:start": "2026-03-31",
  "date:日時:is_datetime": 0,
  "userDefined:URL": "https://example.com/...",
  "Privacy": "Public"
}
```
> **デフォルト値**: Priority=緊急、Privacy=Public。ユーザーから別途指定がある場合のみ変更する。

**contentの例（応募系タスク）:**
```markdown
## 概要
Love Voice mag. のアンケートハガキを使って、月音こなサイン入りチェキプレゼント（A）に応募する。

## 応募方法
- 本誌に封入されたアンケートハガキのプレゼント希望欄の **（A）に丸** をつけて投函
- 抽選で **4名様** にプレゼント

## 締切
**3月末日（当日消印有効）**

## 注意事項
- 結果は発送をもって発表
- 当選者の権利は譲渡不可
- 転売は禁止
```

**contentの例（予約系タスク）:**
```markdown
## 概要
蓮ノ空女学院スクールアイドルクラブ×サンリオキャラクターズ ティーパーティver. の通販予約を期限までに行う。

## 予約期間
2月13日(金) 17:00 〜 3月15日(日) 23:59:59

## 通販URL
https://premiumstore.jp/item_List.php?@ps@=none&cat=42

## 参考ツイート
https://x.com/LLSPremiumShop/status/...
```

### Step 4: 作成後の対応

- Notionのリンクをユーザーに提示
- 追加のプロパティ変更指示があれば `Notion:notion-update-page` で即座に更新
  - 例: `Privacy` を後から変更、タグの追加、期限の修正等
- ユーザーの短縮入力や誤字にも柔軟に対応（例: 「publicつけて」→ Privacy: Public）

## エラーハンドリング

- URL取得失敗 → 代替手段（検索、関連ページ）を試す → それでもダメならユーザーに情報提供を依頼
- 画像が不鮮明 → 読み取れた部分を提示し、不明点をユーザーに確認
- スキーマ不一致 → ユーザーに選択肢を提示して確認
- Notion API エラー → エラー内容をユーザーに伝え、修正を試みる

## 効率化のガイドライン

1. **既知のDBはスキーマ取得をスキップ** — 毎回fetchせず、キャッシュされたスキーマを使う
2. **確認はまとめて1回で** — `ask_user_input_v0` で複数項目を同時に聞く（最大3問）
3. **Privacyは初回作成時に含める** — 後から更新する手間を省く
4. **自動推測を活用** — タグやステータスは明らかなら自動設定し、確認に含めるだけでよい
5. **ユーザーの意図を汲む** — 短縮入力（「publicつけて」等）も正しく解釈して即対応
