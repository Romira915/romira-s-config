# ユーザー指摘の永続化

## 目的

ユーザーの指摘をその場限りの会話修正で終わらせず、適切なスコープのルールと実装へ反映する。複数のAIツールへ配布される共通指示の正本は `ai-config/CLAUDE.md`、具体的な反映手順はこのスキルを正本とする。ツールごとに同じルール本文を複製してはならない。単発の修正まで蓄積して、将来の判断を過剰に縛らない。

## 発火条件

ユーザーが次のような将来適用の意図を示したら、このスキルを使う:

- 「今後」「常に」「次回から」「二度と」「同じことを繰り返さない」
- 「このスキルだけではない」「全体で適用」「常に改善」
- 同じ誤りを複数回指摘された場合

単発の修正、今回だけの例外、質問への回答、好みの確認だけの場合は永続化しない。

## 手順

1. 共通指示の正本 `ai-config/CLAUDE.md` と、現在のプロジェクトの `CLAUDE.md` / `AGENTS.md` を読み、既存ルールとの重複・矛盾・適用範囲を確認する。必要に応じて `ai-config/rules/` と対象スキルも確認する。
2. 指摘を次のいずれかに分類する:
   - **全体ルール**: すべてのタスクやスキルに適用する判断・安全性・報告方針
   - **プロジェクトルール**: このリポジトリ固有の構成・命名・検証方法
   - **スキルルール**: 特定スキルの手順・除外条件・ツール利用方法
   - **実装ルール**: 設定・スクリプト・コードと、それを守る回帰テスト
3. 全体ルールなら `ai-config/CLAUDE.md` に、発火条件・対応・例外を短く追記する。既存ルールで表現できる場合は重複追記せず、必要な範囲だけ更新する。`ai-config/rules/` や各ツールの設定ディレクトリへ同じ本文を追加しない。
4. 分類したスコープの正本を更新する。全体ルールを特定スキルだけへコピーして済ませない。
5. 同じ誤りを再現できる場合は、回帰テストまたは明示的な検証手順を追加する。テストには保証する内容（What）を書く。
6. `git diff --check` と対象テストを実行し、公開ファイルに個人情報・秘密情報がないことを確認する。
7. 変更ファイル、適用範囲、検証結果を報告する。commit / push は別途明示指示がある場合だけ行う。

## 判断基準

- ユーザーの明示した将来適用の範囲を最優先する。
- 影響範囲が曖昧なときは、最小のスコープへ閉じ込めず、共通ルールに「要確認」として記録してから確認する。
- 個人固有の値はスキルや共通ルールに書かず、必要な場合だけ `~/.claude/personal.md` から読み込む。
- 自動更新とは、指摘を検知したターンでこの手順を実行し、共通の正本または該当する正本へ反映することを指す。会話ログを無条件に解析して設定を書き換えるバックグラウンド処理は行わない。
