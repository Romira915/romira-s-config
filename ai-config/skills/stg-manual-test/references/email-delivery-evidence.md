# メール配信 QA の証拠境界

メール送信、受信、またはメールヘッダーを合格条件に含める場合に読む。

## 宛先の記録

画面上で指定した送信対象と、受信ボックスで観測できた宛先を同一視しない。

- 画面の選択内容は、リスト名、ユーザー種別、選択件数など UI に表示された値として記録する
- 受信結果は、メール原文で観測した `To` / `Delivered-To` として記録する
- リスト展開や転送を含む場合は、UI 上の選択内容と最終受信アドレスをそれぞれ別の証拠で示す

## ヘッダーの観測境界

ヘッダーを合格条件にする前に、どの境界で存在すべきかを特定する。

| 観測境界 | 確認手段の例 | 証明できること |
|---|---|---|
| 送信アプリケーションから配送基盤への投入 | 送信ログ、リクエスト記録、テストダブル | 投入時に付与した内部ヘッダー |
| 配送基盤から最終メールボックスまで | メールボックスの「原文を表示」、ダウンロードした原文 | 最終受信時に残っているヘッダー |

配送途中で削除され得る内部ヘッダーは、最終受信原文に存在しないことだけを根拠に、投入時にも存在しなかったと判定しない。

投入時の証拠を取得できない場合は、メール受信の成否と内部ヘッダーの確認結果を分ける。後者は保留とし、完了に必要なログまたはリクエスト記録を QA 文書へ明記する。
