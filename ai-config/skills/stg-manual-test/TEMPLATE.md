# Jira 貼付用 QA Markdown テンプレート

## ファイル保存先

既存ファイルやユーザー指定があればそれを優先する。指定がなければ `docs/qa/<チケットキー>-STG-QA.md` とする。

このファイル自体を Jira コメントとしてそのまま貼れる内容にする。QA結果を参照するだけの `comment_draft.md` は作らない。

## コメントフォーマット

```markdown
# STGマニュアルテスト結果

## テスト環境

| 項目 | 値 |
|------|-----|
| STG | <STGドメイン> |
| 確認方法 | <mailcatcher / 画面表示 / DB等> |
| 企業 | <テスト企業名>（企業ID: <ID>） ※該当する場合 |
| 実行ツール | <agent-browser CLI / Playwright MCP> |

## テストデータ

<テストデータの説明（テーブル形式）>
<テストデータの変更を行った場合はその旨も記載>

前提条件には、実行者が使用できる必要な状態を書く（例: `有効なトークンがわかっている`）。`CSVから取得済み` のような値の入手経路や、作成者にしか関係しない作業履歴は書かない。

## テスト結果

| # | アクション | 入力条件 | 期待結果 | 実際の結果 | 判定 | エビデンス |
|---|-----------|---------|---------|-----------|------|----------|
| <番号> | <アクション名> | <パラメータ名=値 / 補足> | <具体的な表示内容> | <実際に表示された内容> | OK/NG | <スクリーンショットファイル名> |

## 共通確認事項（該当する場合）

- <横断的な確認項目とその結果>

## エビデンス

<ファイル名と内容の対応表>
```

## テスト結果テーブルの記載ルール

- **#列**: テスト番号（チケットの既存番号体系があればそれに合わせる）
- **入力条件**: `パラメータ名=値` 形式。複数条件は ` / ` 区切り。データ状態の補足も記載
- **期待結果**: 具体的な表示内容（見出し名、フィールド値、エラーメッセージ等）
  - 今回の変更が保証すべき独立した事実だけを書く
  - より強い確認に包含される確認や、同じ意味の言い換えを重ねない
  - チケットの変更内容と直接関係しない確認を追加しない
- **実際の結果**: 期待結果に対応する形で実際に確認した内容（agent-browser CLI の場合は `get text @e<N>` の出力等を根拠にする）
- **判定**: `OK` または `NG`
- **エビデンス**: ブラウザ確認は Jira へ添付するスクリーンショットのファイル名を記載する。CLI 確認は、実行した確認コマンドと実出力を同じセルへ記載し、合否だけを言い換えた要約文にしない
  - CLI の複数行エビデンスを載せる場合は HTML の `<table>` を使い、エビデンスセル内へ `<pre><code class="language-console">` で埋め込む
  - `$ command`、続けて出力の順でコードブロックに入れる
  - 複数のコマンドは、確認目的ごとに見出しとコードブロックを分ける
  - 値の一致は比較コマンドと比較対象の実値を載せる
  - 値の不在は検索条件がわかるコマンドと、`none` または終了ステータスなど不在を判定できる出力を載せる
  - HTTPレスポンスを確認できている場合はcurl終了ステータスを載せない。ZIP展開など、レスポンスだけでは判断できない確認の終了ステータスは載せる
  - ステータス・遷移先・attachmentの不在で拒否を証明できる場合は、本文サイズや「ZIPではない」確認を重ねない
  - Jira 閲覧者がアクセスできないローカルファイルを「詳細」や「エビデンス」として参照させない
  - ローカル絶対パスへのリンクを記載しない。スクリーンショットは Jira 添付後に識別できるファイル名だけを記載する

## スクリーンショットのファイル名規則

- 入力画面: `test<番号>_input.png`
- 結果上部: `test<番号>_<内容>_upper.png`
- 結果下部: `test<番号>_<内容>_footer.png`
